# Valeton GP-5 (CN) → English UI

> **Русская версия** · [English version](README-en.md)

Как мы включили английский интерфейс на китайской Valeton GP-5 **без перепрошивки** —
через штатный, но скрытый механизм активации в приложении Valeton Suite.

**Итог:** язык педали и приложения переключён на английский. Проверено на живом устройстве.

---

## 1. Задача

| | |
|---|---|
| Устройство | Valeton GP-5, китайская (CN) версия, прошивка **V1.0.6** |
| Симптом | интерфейс только на китайском, пункт выбора языка недоступен |
| Хост | macOS (Apple M1) |
| Приложение | Valeton Suite (мобильное — iOS; десктопное — 2.1.0) |
| Цель | английский UI педали |

## 2. Первый (тупиковый) заход: патч прошивки

Начали с очевидного — переписать китайские строки в файле прошивки.

### Что выяснилось про контейнер

Файл `GP-5 Firmware V1.0.6.bin` (2 094 404 байта, sha256 `259ac4e7…baf42`),
магия контейнера — **`HTFW`**, заголовок 0x88 байт:

| смещение | значение |
|---|---|
| 0x00 | `HTFW` |
| 0x04 | **CRC16 (uint16 LE)** по `file[6:]` |
| 0x08 | размер файла |
| 0x0C | строка модели, 16 байт: `GP-5` |
| 0x1C | версия: `V`, major, minor, patch |
| 0x24 | размер полезной нагрузки |
| 0x38/48/58/68/78 | 5 записей разделов по 16 байт |

Разделы: `c`, `g`, `f`, `b` (в нём строки UI), `e`. В каждой записи младшие 16 бит —
тот же CRC16 по всему разделу.

Китайские строки UI лежат в одном блоке `0x162348..0x1624A8` (25 строк),
официальный английский блок — рядом: `0x1624AC..0x1625C8`.

### Защита от копирования в Suite ≥ 2.0

Нативная библиотека `5868USB.dylib` содержит экспорт **`_checkCrc`**: читает файл,
считает **CRC16 (poly 0xA001, init 0xFFFF) по `file[6:]`** и сверяет с uint16 LE по смещению 4.
CRC по всем 5 разделам — тоже проверяются.

Патчер (`patch_to_english.py`) заменяет строки и пересчитывает **все** CRC —
и действительно проходит проверки.

### Почему это было тупиком

> **CN- и глобальная прошивки байт-идентичны.**
> valeton.net == zh.valeton.net == файл с официального онлайн-обновлятора.

Значит, языка в файле прошивки нет вообще: он **не может** быть источником языка.
Перепрошивка (даже идеально пропатченная) ничего бы не изменила.

Дополнительный симптом, который это подтвердил: при попытке обновления приложение писало
*«The firmware file is not compatible with your device»* — **и с оригинальным файлом тоже**.
То есть дело было не в патче.

**Вывод: правильный путь — не файл, а настройка самого устройства.**

## 3. Ключевое открытие: язык — это настройка педали

В официальном руководстве GP-5 (EN) есть пункт глобальных настроек:

> **`LANG` — For choosing your system language.**

То есть язык хранится в самом устройстве; на CN-экземплярах он «залочен» (в меню доступен только
китайский). А приложение умеет этот язык **задавать** — командой по MIDI/BLE.

## 4. Реверс приложения

Разобрали Android-APK (`Valeton_Suite_1.1.2.apk`, sha256 `8f4512ac…`) через **Blutter**
(пакет `gp_5`, выход — `blutter_out/`).

### Протокол

| команда | смысл |
|---|---|
| `0x32` (50) | `requestDeviceUUID` — запросить у педали её Device ID |
| `0x33` (51) | `sendLanguage` — установить язык педали |

Пакеты идут SysEx: байты кодируются в полубайты, обрамляются `0xF0 … 0xF7`,
внутри — команда, параметры и CRC8 (poly 0x1D, init 0). Отправка — `HtDevice::addSendData`.

### Скрытый диалог

В приложении есть `SetLanguageDialog` («Set Language»):

* открывается **скрытым жестом** — 3 быстрых тапа подряд (< 1.5 с) по карточке/картинке
  устройства на странице настроек (`GlobalSettingPage::_handleTap`);
* открывается только если Device ID уже получен от педали;
* содержит **Device ID** с кнопкой *Copy*, одно поле ввода и кнопки Cancel / OK.

### Код активации — полностью разобран

Файл `utils/information_encryption_util.dart`, класс `CustomCipher`.

```
key      = utf8(deviceId)
enc[i]   = ror8( byte_i XOR key[i % len(key)], 2 )
dec[i]   = rol8( byte_i, 2 ) XOR key[i % len(key)]
```

Формат кода (hex-строка):

```
[длина ключа: 1 байт] [ключ] [зашифрованный payload]
```

При проверке приложение убеждается, что `String.fromCharCodes(ключ) == Device ID`.
Payload — JSON:

```json
{"start_date": …, "end_date": …, "languages": [...]}
```

`languages` — список языков; `getLanguage()` превращает его в код, который потом уходит в педаль:

| список | код |
|---|---|
| `[]` | `0000` |
| `["英文"]` | `0001` (только английский) |
| `["中文"]` | `0002` (только китайский) |
| `["中文","英文"]` | `0003` (оба) |

Далее приложение собирает `generateEncryptedData(код + deviceId, key = deviceId)`
и отправляет в педаль командой **0x33**.

Дополнительно: устройство **само сообщает** свой язык одним числом —
**1 = китайский, всё остальное = английский** (`GlobalModel::updateGlobalLanguage` → `"zh"`/`"en"`).
Именно эту ветку патчит известный проект `flameshikari/valeton-suite-en` (только у приложения,
не у педали).

## 5. Главная засада: секунды vs миллисекунды

Это стоило больше всего времени.

В **старой** сборке (Android 1.1.2) `start_date` / `end_date` — **unix-секунды**,
и функция сама умножает их на 1000.

**Текущее мобильное приложение ожидает unix-МИЛЛИСЕКУНДЫ.** Если положить секунды:

* интервал действия уезжает в январь 1970 года;
* `now > end_date` → проверка срока не проходит;
* приложение отвечает **«Please enter the correct activation code»** — для **любого**
  формально правильного кода.

С миллисекундами всё принимается. `gp5_lang_unlock.py` теперь использует мс по умолчанию.

## 6. Рабочий рецепт

1. Подключить педаль (BLE; на педали долгое нажатие ручки **PARA** включает сопряжение).
2. В приложении открыть страницу настроек устройства и вызвать скрытый диалог
   (**3 быстрых тапа по карточке/картинке устройства**).
3. Нажать **Copy** — в буфере окажется строка Device ID, например
   `4d15070808090505` (у каждой педали своя).
4. Сгенерировать код:

   ```bash
   python3 gp5_lang_unlock.py --device-id "$(pbpaste)"
   ```

5. Вставить код в поле и нажать **OK** → *«Unlocked successfully.»*
6. Интерфейс педали переключается на английский; приложение подхватывает язык педали
   и тоже переключается.

## 7. Инструмент `gp5_lang_unlock.py`

```bash
# английский (код 0001) — то, что нужно в 99% случаев
python3 gp5_lang_unlock.py --device-id <DEVICE_ID>

# оба языка (0003)
python3 gp5_lang_unlock.py --device-id <DEVICE_ID> --both

# только китайский (0002)
python3 gp5_lang_unlock.py --device-id <DEVICE_ID> --zh

# расшифровать/проверить существующий код
python3 gp5_lang_unlock.py --device-id <DEVICE_ID> --decode <CODE>

# самопроверка шифра (encrypt → decrypt round-trip)
python3 gp5_lang_unlock.py --self-test
```

Флаги: `--days N` — срок действия в днях (по умолчанию 3650).
Скрипт зависит только от стандартной библиотеки Python 3.

## 8. Результат

* Педаль: интерфейс на английском.
* Приложение: переключилось на английский вслед за педалью.
* Прошивка **не менялась** — файл остался заводским.

Для конкретной проверенной педали (Device ID `4d15070808090505`) — пример с

## 9. Полезные детали и грабли

* **Device ID — это ровно та строка, что копирует кнопка Copy** (проверено побайтово:
  `pbpaste | xxd`), без пробелов и переводов строк. Она же — ключ шифра.
* Сам шифр между версиями **не менялся**: он одинаков и в Android 1.1.2, и в десктопной 2.1.0
  (проверено дизассемблированием: `eor` → `asr #2` → `and #3` → `lsl #6` → `orr`
  и обратная ветка `asr #6` / `and #0x3f` / `lsl #2`).
* **Тосты в мобильном приложении могут быть не видны** — на iOS клавиатура перекрывала
  всплывающее сообщение. Если «ничего не происходит», проверяйте с закрытой клавиатурой.
* Текст сообщения об ошибке одинаков во всех сборках — «Please enter the correct activation
  code» (iOS, Android 1.1.2, десктопная 2.1.0).
* Десктопная **Valeton Suite 1.0.9** этой функции **не имеет** — нужна **2.1.0+**.
* Скрытый диалог требует, чтобы Device ID был получен, т.е. педаль должна быть подключена.

### Что не сработало и почему (чтобы не повторять)

| Гипотеза | Итог |
|---|---|
| Патч строк в прошивке | Прошивки CN и global идентичны — язык не в файле |
| Версия прошивки 1.0.7 / 9.9.9 | То же сообщение «not compatible» |
| Другой кабель / другой USB-порт | Кабель и MIDI-линк исправны |
| Даты в секундах | Приложение ждёт миллисекунды |
| Другие варианты ключа (uppercase, байты, реверс) | Ключ — именно строка Device ID как есть |
